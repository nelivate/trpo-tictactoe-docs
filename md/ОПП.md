# 1. Назначение программы

## 1.1. Функциональное назначение

Программа «Крестики и нолики» предназначена для организации сетевой игры между двумя пользователями на поле 25 × 25 с условием победы «пять в ряд». Сервер хранит состояние поля, проверяет ходы и определяет результат; клиент отображает подтверждённое сервером состояние.

## 1.2. Эксплуатационное назначение

Программа применяется в локальных сетях учебных классов и на персональных компьютерах под управлением Windows 10/11. Роли пользователей: игрок — участвует в партиях и пользуется чатом; администратор — запускает сервер, следит за базой данных и журналами, управляет учётными записями.

## 1.3. Основные функции программы

– авторизация пользователей и защита учётных записей;

– создание и редактирование профиля игрока;

– создание игровой сессии и подключение второго игрока по идентификатору;

– выполнение ходов на поле 25 × 25 и синхронизация состояния;

– определение победы по пяти символам в ряд и ничьей;

– чат двух игроков с фильтрацией нецензурной лексики;

– автоматический подсчёт баллов и итоговый счёт;

– хранение профилей, результатов и сообщений в PostgreSQL.

Таблица 1 — Требования к техническим средствам

## 2.2. Требования к программным средствам

Серверное программное обеспечение: Docker Engine 24+ и Docker Compose v2, контейнер server с .NET 10 Runtime, контейнер db с PostgreSQL 15+. Клиентское программное обеспечение: release-сборка Flutter для Windows; Flutter SDK на компьютер пользователя не устанавливается. Для работы проведения испытаний и эксплуатации используется доверенная локальная сеть без выхода в Интернет; Docker port mapping допускается.

## 2.3. Требования к квалификации персонала

Игроку достаточно базовых навыков работы с ПК, клавиатурой и мышью. Администратор должен уметь запускать Docker Compose, просматривать журналы контейнеров, создавать резервные копии и работать с PostgreSQL.

# 3. Описание задачи и выполняемых функций

## 3.1. Описание решаемых задач

Задача программы — предоставить двум пользователям возможность провести сетевую партию в «Крестики и нолики» с серверной проверкой всех действий. Один игрок создаёт сессию и сообщает её идентификатор второму; после подключения сервер инициализирует поле 25 × 25, назначает символы X и O и передаёт право первого хода.

Во время партии игроки по очереди выбирают клетки. Сервер проверяет очерёдность, диапазон координат 0–24 и свободность клетки, записывает символ и проверяет пять в ряд. При победе или ничьей партия завершается, результат и баллы сохраняются в базе данных. При выходе игрока или потере связи сессия отменяется, баллы не начисляются.

## 3.2. Порядок выполнения технологического цикла

Порядок работы администратора:

1. Установить Docker Desktop (Windows) или Docker Engine (Linux).

2. Перейти в каталог проекта и выполнить docker compose up -d --build.

3. Убедиться, что контейнеры db и server запущены и healthy.

4. Проверить журнал командой docker compose logs -f server.

5. При необходимости создать учётные записи командой docker compose run --rm server --create-user &lt;login&gt;.

6. Открыть порт 5000 в брандмауэре, если клиенты работают на других компьютерах.

Порядок работы игрока:

1. Запустить клиентское приложение.

2. Ввести адрес сервера и порт.

3. Пройти авторизацию по логину и паролю.

4. При необходимости открыть профиль и изменить никнейм.

5. Создать игровую сессию или ввести идентификатор существующей.

6. Дождаться подключения второго игрока.

7. По очереди выбирать клетки на поле 25 × 25.

8. При необходимости отправлять сообщения в чат.

9. После завершения партии просмотреть результат и итоговый счёт.

10. Выйти из игры или создать новую сессию.

## 3.3. Особенности выполнения программы

При создании сессии первый игрок получает статус хоста и идентификатор комнаты. Второй игрок подключается по этому идентификатору. Третий игрок не может подключиться к занятой сессии; сервер возвращает сообщение о занятости. Правила начисления баллов: 3 балла за победу, 1 балл за ничью, 0 баллов за поражение. Итоговый счёт отображается обоим игрокам после завершения партии и сохраняется в профиле.

## 4.3. Хранение данных

Профили, сессии, результаты и сообщения хранятся в PostgreSQL в таблицах Users, UserProfiles, GameSessions, GameResults и ChatMessages. Данные размещаются в томе pgdata; резервная копия создаётся командой pg_dump и хранится вне рабочего тома. Порт PostgreSQL наружу не публикуется.

# 5. Оценки погрешностей и ограничения

– в одной игровой сессии участвуют не более двух игроков;

– поле фиксированного размера 25 × 25;

– работа в локальной сети без выхода в Интернет; Docker port mapping допускается;

– клиент работает под Windows 10/11, сервер — в Linux-контейнере Docker;

– автоматическое переподключение к начатой партии не поддерживается;

– мини-игра выбора первого хода и список друзей не поддерживаются;

– для работы необходима запущенная СУБД PostgreSQL в контейнере db.

Погрешность синхронизации определяется задержкой локальной сети и не превышает 1 с по пункту 4.1 ТЗ. Погрешность измерения времени — ±0,05 с. Баллы целочисленные, погрешность начисления отсутствует.

# 6. Сообщения оператору и обработка ошибок

Основные сообщения приведены в таблице 4.

Таблица 4 — Основные сообщения об ошибках

| Сообщение | Причина | Действие |
| --- | --- | --- |
| Неверный логин или пароль | Ошибка в учётных данных | Проверить логин и пароль |
| Заполните логин и пароль | Пустые поля | Заполнить оба поля |
| Сессия не найдена | Неверный идентификатор | Проверить номер сессии |
| Сессия заполнена | В сессии уже два игрока | Создать новую сессию |
| Сейчас ход другого игрока | Нарушена очередь | Дождаться своего хода |
| Клетка уже занята | Выбрана занятая клетка | Выбрать свободную клетку |
| Координаты вне диапазона | Значение меньше 0 или больше 24 | Выбрать клетку в диапазоне 0–24 |
| Партия не найдена или не активна | Сессия закрыта | Создать новую партию |
| Соединение потеряно | Обрыв сети или остановка сервера | Проверить сеть и перезапустить клиент |

При ошибке состояние поля не изменяется. Сообщение содержит текст, понятный пользователю; для администратора дополнительно ведётся журнал сервера в файле /app/logs/server.log.
